Chapter 2 built one logistic regression unit. This chapter stacks a row of them — and that row is a neural network.

By the end you will implement forward propagation and backpropagation for a 2-layer network, vectorised across all m examples, with no explicit loop.

Overview · where we came from

Logistic regression, twice over

A neural network is a stack of logistic regression objects. The second layer takes the first layer's output as its input — and that is the whole idea.

Computing the output · the rule to memorise

One rule covers
every layer

W⁽ˡ⁾ : ( n⁽ˡ⁾ , n⁽ˡ⁻¹⁾ ) rows = neurons in this layer · columns = neurons in the previous layer
b⁽ˡ⁾ : ( n⁽ˡ⁾ , 1 ) one bias per neuron in this layer

Where n⁽ˡ⁾ is the number of neurons in layer l, and n⁽ˡ⁻¹⁾ is the number in the layer before it.

Read it right to left: W⁽ˡ⁾ takes something of size n⁽ˡ⁻¹⁾ in, and gives something of size n⁽ˡ⁾ out. We reuse this rule in Chapter 4 for networks of any depth.

Vectorising · the naive version

The obvious way uses a loop

for i = 1 to m:
  z⁽¹⁾⁽ⁱ⁾ = W⁽¹⁾x⁽ⁱ⁾ + b⁽¹⁾   # (n⁽¹⁾, 1)
  a⁽¹⁾⁽ⁱ⁾ = σ(z⁽¹⁾⁽ⁱ⁾)      # (n⁽¹⁾, 1)
  z⁽²⁾⁽ⁱ⁾ = W⁽²⁾a⁽¹⁾⁽ⁱ⁾ + b⁽²⁾ # (1, 1)
  a⁽²⁾⁽ⁱ⁾ = σ(z⁽²⁾⁽ⁱ⁾)      # (1, 1)

This is correct — and it is slow. One pass through the whole training set costs m trips around a Python loop.

Stack the examples in columns and the loop disappears.

Vectorising · the version you implement

Four lines, no loop

Z⁽¹⁾ = W⁽¹⁾A⁽⁰⁾ + b⁽¹⁾  # (n⁽¹⁾, m)
A⁽¹⁾ = g⁽¹⁾(Z⁽¹⁾)      # (n⁽¹⁾, m)
Z⁽²⁾ = W⁽²⁾A⁽¹⁾ + b⁽²⁾  # (1, m)
A⁽²⁾ = σ(Z⁽²⁾)        # (1, m)

We write A⁽⁰⁾ instead of X, because the input is the activation of layer 0. Now every line has the same form — which is exactly what makes Chapter 4's deep version a one-line loop.

Notice: m is always the number of columns.

Vectorising · reading the matrices

Columns are examples,
rows are neurons

Move across a row and you change training example. Move down a column and you change hidden neuron. Same convention as X in Chapter 2.

Part 4
Activation
Functions
Activations · the menu

Four choices for g(z)

So far we have only used sigmoid. In the hidden layers, the other three are almost always better.

Activations · sigmoid vs tanh

tanh is a shifted sigmoid
— and it is better

SIGMOID

range [0, 1]

A = 1 / (1 + np.exp(−z))

Output is always positive, so the mean of a layer's output sits around 0.5 — it does not centre the data for the next layer.

TANH

range [−1, 1]

A = np.tanh(z)

Mean of the output is closer to zero, which centres the data for the next layer. Usually works better in hidden units.

You can also write tanh by hand: (np.exp(z) − np.exp(−z)) / (np.exp(z) + np.exp(−z)).

Activations · the shared weakness

Both go flat at the ends

If z is very large or very negative, the slope is near zero. Gradient descent multiplies by that slope — so the updates become tiny and learning slows to a crawl.

Activations · the fix

ReLU keeps the slope

ReLU = max(0, z) if z is negative the slope is 0 — if z is positive the slope stays 1
RELU

max(0, z)

The default choice for hidden layers. No saturation on the positive side, so learning stays fast.

LEAKY RELU

max(0.01z, z)

Gives a small slope for negative z instead of zero. Works at least as well — but most people still use plain ReLU.

the 0.01 can itself be a parameter of your algorithm

Activations · the practical rule

What to actually use

  • →Hidden layers: use ReLU. If you want to experiment, try tanh or leaky ReLU.
  • →Output layer, binary classification: use sigmoid — you need an answer between 0 and 1.
  • →Output layer, regression: a linear activation is fine. If the output cannot be negative, use ReLU instead.

There are no guidelines beyond this. Try them on your own problem and measure.

Activations · and everything else you pick

Decisions the data
will not make for you

MOST IMPORTANT

Learning rate

The single choice that most often decides whether training works at all.

STRUCTURE

Layers & neurons

How many hidden layers, and how many neurons in each one.

Plus the activation function for each layer, the number of iterations, and more. Chapter 4 gives these a name: hyperparameters.

Activations · why they are not optional

Drop g, and the whole
network collapses

Suppose you remove the activation — that is, use a linear activation g(z) = z. Then the layers compose like this:

a⁽¹⁾ = W⁽¹⁾x + b⁽¹⁾
a⁽²⁾ = W⁽²⁾a⁽¹⁾ + b⁽²⁾
    = W⁽²⁾(W⁽¹⁾x + b⁽¹⁾) + b⁽²⁾
    = (W⁽²⁾W⁽¹⁾)x + (W⁽²⁾b⁽¹⁾ + b⁽²⁾)
    = W′x + b′   # just one linear function

However many hidden layers you add, the output is still linear — no better than logistic regression.

Activations · the one exception

One place linear
is allowed

The output layer of a regression problem — where y is a real number, not a 0/1 label.

Predicting a house price, for example: the answer can be any positive number, so squashing it into [0, 1] would be wrong.

Even then, if the output cannot be negative — a price, a length, a count — ReLU in the output layer is a better fit than a plain linear unit.

Hidden layers: never linear.

Question

Why must hidden layers use a
non-linear activation function?

  • ABecause non-linear functions are faster to compute.
  • BBecause composing linear functions gives another linear function, so extra layers would add nothing.
  • CBecause gradient descent only works on non-linear functions.
  • DBecause the output must lie between 0 and 1.

B. A stack of linear layers collapses into a single W′x + b′. D describes the output layer of a binary classifier — a different concern, and it does not explain the hidden layers.

Activations · derivatives for backprop

Every g, and its g′

Activationg(z)g′(z)Note
Sigmoid1 / (1 + e−z) g(z)(1 − g(z))reuse the value you already computed in the forward pass
tanh(ez − e−z) / (ez + e−z) 1 − g(z)²also written 1 − tanh(z)²
ReLUmax(0, z) 0 if z < 0 · 1 if z ≥ 0undefined exactly at z = 0; in code we just pick 1
Leaky ReLUmax(0.01z, z) 0.01 if z < 0 · 1 if z ≥ 0same shape, with a floor instead of zero

The sigmoid and tanh derivatives are written in terms of g(z) itself — so backprop can reuse the activation it already has, instead of recomputing the exponentials.

Gradient descent · what we are optimising

Four things to learn

n⁽⁰⁾ = nx    n⁽¹⁾ = hidden neurons    n⁽²⁾ = 1
W⁽¹⁾ (n⁽¹⁾, n⁽⁰⁾)   b⁽¹⁾ (n⁽¹⁾, 1)   W⁽²⁾ (n⁽²⁾, n⁽¹⁾)   b⁽²⁾ (n⁽²⁾, 1)
J(W⁽¹⁾, b⁽¹⁾, W⁽²⁾, b⁽²⁾) = (1/m) Σ ℒ(A⁽²⁾, Y) same cost function as Chapter 2 — now with four parameters instead of two

Gradient descent does not change. It still steps downhill on J — there are simply four things to update instead of two.

Gradient descent · the training loop

Repeat until it stops improving

Repeat:
  compute the predictions ŷ⁽ⁱ⁾, i = 1…m  # forward
  get the derivatives dW⁽¹⁾, db⁽¹⁾, dW⁽²⁾, db⁽²⁾  # backward
  W⁽¹⁾ = W⁽¹⁾ − α · dW⁽¹⁾
  b⁽¹⁾ = b⁽¹⁾ − α · db⁽¹⁾
  W⁽²⁾ = W⁽²⁾ − α · dW⁽²⁾
  b⁽²⁾ = b⁽²⁾ − α · db⁽²⁾

Exactly the Chapter 2 update rule — param = param − α · dparam — applied four times.

Gradient descent · forward

Forward propagation

Z⁽¹⁾ = W⁽¹⁾A⁽⁰⁾ + b⁽¹⁾  # A⁽⁰⁾ is X
A⁽¹⁾ = g⁽¹⁾(Z⁽¹⁾)
Z⁽²⁾ = W⁽²⁾A⁽¹⁾ + b⁽²⁾
A⁽²⁾ = σ(Z⁽²⁾)

The last layer uses sigmoid because the output is a probability between 0 and 1. The hidden layer uses whatever g⁽¹⁾ you chose — usually ReLU.

Gradient descent · backward

The six equations

dZ⁽²⁾ = A⁽²⁾ − Y
dW⁽²⁾ = (dZ⁽²⁾ A⁽¹⁾ᵀ) / m
db⁽²⁾ = sum(dZ⁽²⁾) / m
dZ⁽¹⁾ = (W⁽²⁾ᵀ dZ⁽²⁾) ∗ g′⁽¹⁾(Z⁽¹⁾)
dW⁽¹⁾ = (dZ⁽¹⁾ A⁽⁰⁾ᵀ) / m  # A⁽⁰⁾ = X
db⁽¹⁾ = sum(dZ⁽¹⁾) / m
  • ∗is an element-wise product, not a matrix multiply.
  • ᵀthe transposes are there to keep the dimensions right.
  • /mbecause J is an average over the m examples.
Gradient descent · how the equations arise

Backward is the chain rule

dZ⁽²⁾ = A⁽²⁾ − Y is the derivative of the logistic cost times the derivative of the sigmoid — the two collapse into that one clean expression.

Initialization · why zeros fail

All-zero weights make
identical neurons

With W = 0 every hidden unit computes the same function, and every gradient descent step updates them the same way. Four neurons, but only one distinct feature — forever.

Initialization · what to write

Small random numbers

W1 = np.random.randn((2,2)) * 0.01  # small enough
b1 = np.zeros((2,1))              # zero is fine here
W — RANDOM

breaks symmetry

Different starting weights means the hidden units learn different features.

b — ZERO

safe at zero

The bias does not cause the symmetry problem — as long as W is random, the units already differ.

Initialization · why the numbers must be small

Big weights land you
in the flat zone

If W starts large, then Z = Wx + b is large on the very first step — and tanh or sigmoid is already saturated before training begins.

Saturated means slope near zero, which means slow learning — the exact problem from the activation slides, now self-inflicted at initialisation.

If your network has no sigmoid or tanh anywhere, this matters less. But the habit is worth keeping.

0.01 is fine for a one-hidden-layer network. For deep networks the constant changes — but it stays small.

Question

You initialise W⁽¹⁾ and b⁽¹⁾ both to zero.
What happens?

  • ATraining works normally — the weights move apart on the first iteration.
  • BEvery hidden unit computes the same function, and they stay identical on every iteration.
  • CThe cost function becomes non-convex.
  • DNothing — only b needs to be random.

B. This is the symmetry breaking problem. It is W that must be random — D has it exactly backwards, since b = 0 is perfectly safe.

Chapter 3 · recap

What to carry forward

  • 01A neural network is a stack of logistic regression units.
  • 02The input layer is not counted — one hidden layer plus an output layer is a 2-layer network.
  • 03W⁽ˡ⁾ is (n⁽ˡ⁾, n⁽ˡ⁻¹⁾) and b⁽ˡ⁾ is (n⁽ˡ⁾, 1).
  • 04Stack examples in columns: Z⁽ˡ⁾ and A⁽ˡ⁾ are (n⁽ˡ⁾, m) — m is always the column count.
  • 05Use ReLU in hidden layers, sigmoid in a binary output layer.
  • 06Hidden layers must be non-linear, or the network collapses into one linear function.
  • 07Backprop is six equations, with one element-wise product at dZ⁽¹⁾.
  • 08Initialise W randomly and small; b may be zero.
